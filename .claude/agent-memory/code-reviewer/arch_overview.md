Each integration bundle lives under `aws/<name>/` or `trafficpeak/<name>/` and contains:
- `bundle.json` — full descriptor (base_url, metadata, tables, transforms, dependencies, ui)
- `bundle-config.json` — lightweight CI config (data_category, table_name, version, folder)
- `dashboards/`, `transformations/`, `functions/` subdirectories

Two-track CI (`bundle-ci.yml`):
- Track 1 (full): runs configure → validate → commits formatted output and portables/
- Track 2 (validate-only): runs Rust validator only
- Track routing determined by `scripts/detect_track.py` based on presence of `.originals/` and asset state

`portables/` output layout: `portables/<source>/<bundle>/<version>/` (e.g., `portables/trafficpeak/security/0.9.0/`)
Push-to-cac workflow (`push-to-cac-tools.yml`) syncs portables/ to `cac-tools/data/bundles/` on merge to main.

`bundle.json` `base_url` field points to the GitHub blob URL for the bundle directory. It is auto-generated by `scripts/configurator/config.py` and used in runbook generation.

`bundle.json` `dependencies.hydrolix.shared_functions` lists functions the bundle depends on. Functions under `functions/` directory may exceed those listed — undeclared functions are not an error but may not be deployed.

`ui.folder` field in `bundle.json` is read by `bundle_to_yaml.py` to determine Grafana folder nesting. As of this review no bundle in the repo declares `ui.folder` — all fall back to the legacy portables path.

`trafficpeak/security` is a Trafficpeak (Akamai) integration bundle at metadata version 0.9.0.
The portables output is at `portables/trafficpeak/security/0.9.0/` (legacy path, no category subfolder since ui.folder is absent).
